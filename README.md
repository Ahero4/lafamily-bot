# LaFamily Bot — Python, версия 0.6.0

Семейный Discord-бот на **Python 3.12+** и **discord.py**. Возможности: учёт мероприятий (МП), общие баллы, сборы коровника, проверка ников и сравнение цен скупщиков с подписками. Код разделён на модули и снабжён комментариями на русском языке.

## Новые возможности 0.6.0

| Команда | Назначение и доступ |
|---|---|
| `/баллы история [страница]` | Личная история начислений, базы, бонусов и отмен, по 5 отчётов. Всем участникам. Полная причина отмены — в `/мп посмотреть`. |
| `/участник профиль [участник]` | Общие и недельные баллы, участие, победы и MVP. Личные подписки показываются только владельцу. |
| `/баллы ведомости создать банк:… [неделя]` | Администратор сохраняет снимок премий; по умолчанию прошлая неделя. Баллы и деньги не списываются. |
| `/баллы ведомости список [страница]`, `посмотреть номер:…` | Сохранённые ведомости, состояние и полная выгрузка CSV для администратора. |
| `/баллы ведомости статус номер:… статус:…` | С личным подтверждением: Подготовлена → Утверждена → Выплачена. Одна утверждённая ведомость на точный период. Суммы сохраняются при поздних отменах отчётов; выплата — ручная отметка. |
| `/скупщик проверить-лс` | Одно тестовое ЛС по запросу участника, не чаще раза в минуту. Подписки и их циклы сохраняются. |
| `/скупщик история товар:… [дней]` | История за 1–366 дней: таблица, полный CSV и самостоятельный график SVG для открытия в браузере. Данные начинают собираться с 0.6.0. |
| `/мп запись создать название:… начало:… [мест]` | Организатор открывает запись на будущее МП, начало по Москве, 1–100 мест. Основной состав, резерв в порядке записи, Возможно и отказ. |
| `/мп запись состав номер:…` | Всем с доступом к каналу МП: основные участники, резерв, Возможно. В сообщении до 50 человек в каждой группе; весь список в CSV. |
| `/мп запись закрыть номер:…` | Руководство закрывает запись; после наступления начала запись закрывается автоматически по времени. |
| `/мп запись отчёт номер:… вид:…` | После начала организатор переносит основной состав в обычный черновик. Фактическое участие, итог и MVP нужно проверить перед подтверждением; резерва и Возможно в начислениях нет. |
| `/бот диагностика` | Администратору: SQLite quick_check, число отчётов/участников/баллов, основные каналы и права, время успешного бэкапа. |
| `/бот операции [страница]` | Администратору: по 15 записей из выборки последних незавершённых операций каждого типа. Это диагностический список, полный журнал ЛС — `/скупщик статистика`. |
| `/бот восстановить-операцию операция:… [номер]` | Администратор обновляет/восстанавливает карточку отчёта либо повторяет очистку учтённых ЛС скупщика. Повторных начислений нет. Неоднозначные отправки не повторяются вслепую. |

Перед отменой `/мп отменить` бот показывает общую сумму исключаемых баллов и число участников и ждёт подтверждения владельца запроса (3 минуты). Похожие отчёты одного вида с пересечением состава в пределах 30 минут требуют кнопки «Разрешить похожий отчёт» и повторного подтверждения. Изменение состава/наград/данных или появление нового похожего отчёта сбрасывает разрешение. Это предупреждение, не запрет проводить два отдельных МП подряд.

Автоматические анонсы получают постоянные кнопки записи на конкретное событие (100 мест по умолчанию). Для отдельной карточки с другим лимитом используйте `/мп запись создать`. Записи, резерв и привязка карточки хранятся в SQLite и переживают перезапуск; список может отличаться от фактического участия, начислений при записи нет.

Цены каждого полного обработанного отчёта сохраняются отдельно от очищаемого канала. История использует последнюю редакцию каждого исходника и дату первого получения. Таблица показывает диапазон цен всех скупщиков за день; график — лучшую цену дня. Старые данные до установки автоматически не восстанавливаются.

Очередь ЛС группирует товары одного получателя и текущего запуска. При превышении лимита текста список разбивается на несколько сообщений. Новые сообщения включают время по Москве и учитываются для безопасной очистки из 0.5.3. Журнал по товарам сохраняется; сводка и динамика считают реальные сгруппированные сообщения, в детальном CSV есть message_group. До отправки перепроверяются текущие цены, возраст задачи (не более часа), свежий участник и доступ к каналу. Не начатые задачи продолжаются после перезапуска; прерванные начатые становятся uncertain. Безопасный повтор сетевого сбоя до отправки ограничен тремя попытками с паузой 30 секунд. Сами запросы соблюдают ограничения через discord.py.

Диагностика раз в 10 минут отправляет в канал `/бот отчёты` только изменившийся набор проблем. Отслеживает давность успешного бэкапа (7 часов), основные права, недоступные каналы, проблемные доставки и уменьшение сохранённых показателей истории. Снижение баллов из-за отмены не считается потерей БД. Новая пустая база показывается как предупреждение; контрольная точка внутри БД не является внешней гарантией обнаружения полной подмены базы.

При восстановлении карточки отчёта сначала проверяется история канала: найденная карточка привязывается без новой отправки. Новая публикация блокируется после неоднозначного результата; требуется ручная проверка. Для решений по заявкам остаются существующие кнопки восстановления. Повторная очистка затрагивает только зарегистрированные ЛС скупщика.

### Проверки и автодеплой

`.github/workflows/checks.yml` запускает синтаксическую проверку и весь unittest-набор на Python 3.12 для push/PR в main. Только успешный push актуальной main продвигается без force в ветку `deploy`. PR имеет права только чтения, продвижение — отдельная задача с contents:write. Секреты Discord и рабочая БД для проверок не нужны.

**Однократная настройка на Bothost:** после публикации изменений и успешного GitHub Actions выбрать ветку `deploy` вместо `main` в настройках автодеплоя. До переключения хостинг продолжает прежний автодеплой main. Не удалять постоянный каталог БД и не менять DATABASE_PATH. Настройки панели хостинга этот выпуск автоматически не изменяет.

## Ранее доступные возможности

В уведомлениях скупщика с версии 0.5.3 указаны дата и время отправки по Москве. После успешной публикации нового полного отчёта либо изменения цен в текущем отчёте бот удаляет ЛС от прежнего отчёта/редакции, даже если новых сигналов нет. Ручная обработка очищает устаревшие ЛС без рассылки. Одинаковый повтор отчёта и обработка более старого источника не удаляют актуальные ЛС. Новые сигналы по-прежнему появляются только после выхода цены из выбранного условия и повторного входа.

Удаляются только новые ЛС скупщика с сохранёнными в `price_dm_messages` ID: перед удалением сверяются бот, личный канал, получатель, ID и хеш текста. История других сообщений в ЛС не просматривается и не очищается. Не совпавшее с реестром сообщение сохраняется. Старые ЛС до версии 0.5.3, неоднозначные отправки и сообщения, ID которых не удалось записать, автоматически не удаляются. `price_dm_current` и очередь удаления сохраняются в SQLite; после сетевой ошибки очистка повторится при следующей обработке актуального полного отчёта. Удаление не меняет историю успешной доставки и подписки. Для применения обновите код и перезапустите бота.

- `/инфо общее` — команды участников и организаторов, параметры, пояснения и назначенные роли; ответ виден только вам. `/помощь` открывает ту же справку. Настройки и управление вынесены в `/инфо админ`.
- Настройка канала отчётов и ролей организатора/руководства командами Discord.
- Добавление видов МП, изменение ставки и отключение без удаления истории.
- Черновик отчёта: вид, дата по Москве, примечание, выбор участников и подтверждение.
- Самозапись через общую кнопку «Участвовать»: участник сразу входит в состав без отдельного одобрения организатором. Организатор также может добавлять людей через меню по 25 человек за раз. Максимум 100 участников, дубли исключаются. Организатор не входит в состав автоматически.
- Начисление очков сразу после подтверждения организатором, без согласования старшим.
- Просмотр отчёта по номеру и отмена руководством с обязательной причиной.
- Личная статистика и рейтинг за текущую или прошлую неделю, по 20 человек на страницу.
- `/баллы общие` — только для администратора Discord: очки каждого участника за всё время и текущую московскую неделю в одном списке. Сортировка по общим очкам, по 20 участников на страницу (`страница:2` и далее). Показаны участники, у которых есть хотя бы один действующий отчёт; отменённые отчёты исключаются. Ответ виден только администратору.
- `/ники проверить` — только администратору: проверка имён всех участников сервера либо только выбранной роли; боты пропускаются. Ники не меняются; уведомления с тегами отправляются только после отдельного подтверждения администратора. Ответ личный, длинный список нарушений прикладывается файлом.
- Сборы коровника с фиксированной наградой, включённые в общую статистику.
- Автоматическое сравнение цен скупщиков, подписки на максимальные цены и очистка канала с сохранением закреплений.
- `/старт участник` — личное знакомство с ботом; `/бот статус` — публичное сообщение о готовности, версии и последнем обновлении.
- SQLite, журнал важных изменений и команда резервного копирования.

Неделя: понедельник 00:00 — следующий понедельник 00:00 по Москве. Начисления относятся к дате проведения МП. Старые отчёты разрешены; закрытия недель пока нет. Изменение ставки применяется к новым черновикам; существующие черновики и отчёты сохраняют показанные очки.

## Установка на Windows

Нужен Python 3.12 или новее. Откройте терминал в `M:\VSCodeDev\lafamily-bot`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Создайте в корне проекта файл `.env` с параметрами ниже; файл `.env.example` в текущем проекте отсутствует. Команды создания окружения и установки нужны на новом компьютере/сервере. Если окружение уже есть, не создавайте его повторно. Если Windows не находит `python`, установите Python с [python.org](https://www.python.org/downloads/) и включите добавление в PATH.

В `.env` заполните:

```dotenv
DISCORD_TOKEN=токен_бота
DISCORD_CLIENT_ID=id_приложения
DISCORD_GUILD_ID=id_вашего_сервера
DATABASE_PATH=./data/lafamily.sqlite
```

Токен храните локально, не отправляйте его в чат и не добавляйте в Git. Относительный путь базы считается от папки проекта. Приложение читает `.env` из этой же папки, даже если запущено из другого места.

Если для доступа к Discord нужен HTTP-прокси, можно дополнительно задать `DISCORD_PROXY=http://127.0.0.1:10809`. По умолчанию подключение прямое. Настройка не обязательна.

## Подключение Discord

1. Создайте приложение в [Discord Developer Portal](https://discord.com/developers/applications). Токен находится в разделе **Bot**, Application ID — в **General Information**.
2. Включите в Discord режим разработчика и скопируйте ID сервера.
3. В OAuth2 URL Generator выберите scopes `bot` и `applications.commands`. Права бота в канале отчётов: **View Channels**, **Send Messages**, **Embed Links**, **Read Message History**. Пригласите приложение по полученной ссылке.
4. Для учёта МП привилегированные intents не требуются. Для `/ники проверить` включите **Bot → Privileged Gateway Intents → Server Members Intent** в Developer Portal и добавьте `DISCORD_MEMBERS_INTENT=true` в `.env`, затем перезапустите бота. Без этой настройки остальные команды продолжают работать, а проверка ников объясняет, что нужно включить. **Message Content Intent** нужен только для модуля цен (описан ниже).
5. Запустите бота — команды зарегистрируются автоматически:

```powershell
.\.venv\Scripts\python.exe main.py
```

При каждом запуске `main.py` бот авторизуется, регистрирует команды **этого приложения на сервере из DISCORD_GUILD_ID**, затем подключается к Discord. При сетевом переподключении регистрация не повторяется. Если регистрация не удалась, запуск завершается с ошибкой; исправьте настройки/соединение и перезапустите процесс. Остановка — Ctrl+C.

На хостинге достаточно команды `python main.py` с установленными зависимостями и настройками окружения. Для обновления загрузите актуальный код и перезапустите процесс. `deploy.py` сохранён для отдельной ручной регистрации без запуска Gateway, но больше не обязателен.

## Первичная настройка

Администратор сервера выполняет:

```text
/бот настройки канал:#отчёты
/мп виды добавить название:Название вашего МП очки:10
```

После `/бот настройки` откроется личная форма с меню «Организаторы» и «Руководство». В каждом выберите от 1 до 25 ролей и нажмите «Сохранить». Достаточно любой одной роли из соответствующего списка. Старые роли переносятся автоматически и выбраны заранее. «Отмена» оставляет настройки без изменений. Все назначенные роли видны в `/инфо общее`.

Название и 10 очков — пример. Готовых видов МП и тарифов нет: их определяет семья. Точное совпадение названия при добавлении обновляет ставку и включает ранее отключённый вид.

Организатор подаёт отчёты. Руководство также управляет видами МП и отменой отчётов. Администратор имеет полный доступ. Остальные участники смотрят виды, отчёты и статистику, записываются на МП, отправляют сборы коровника и управляют личными подписками на цены. Для управляющих ролей нельзя использовать `@everyone`; назначение ролей участникам бот не меняет.

## Первый тест на сервере

1. Добавьте тестовый вид с 10 очками.
2. Организатором выполните `/мп создать` и выберите вид. В общем сообщении черновика два участника могут нажать «Участвовать»; альтернативно добавьте их меню организатора. В поле `дата` можно выбрать подсказку «Сегодня» — бот возьмёт текущую дату и время при создании черновика. Для другого времени введите вручную, например `2026-10-25 12:00` по Москве. Поле можно оставить пустым: это тоже означает момент создания черновика. При подтверждении дата и время не меняются.
3. Проверьте состав и подтвердите отчёт. До подтверждения начислений нет. Черновик действует 1 час; новый черновик заменяет предыдущий этого организатора. При истечении срока или замене бот убирает кнопки и показывает причину.
4. Проверьте публикацию, `/мп посмотреть` и `/баллы рейтинг`.
5. Обычным участником проверьте запрет создания отчётов и управления.
6. Руководством выполните `/мп отменить номер:... причина:Тест`. Начисления исчезнут, отчёт останется в истории со статусом отмены.
7. Перезапустите бота и проверьте сохранение истории. Неподтверждённые черновики после перезапуска нужно создать заново.

Кнопка «Участвовать» остаётся общей и доступной остальным. Повторный клик записанного участника показывает личный ответ «Вы уже участвуете в этом МП» и не добавляет дубль. Личной отключённой кнопки сейчас нет. Запись в состав ещё не начисляет баллы: они учитываются только после итогового подтверждения организатором.

Повторное подтверждение одного черновика не создаёт повторного начисления. Два независимо созданных отчёта об одном реальном МП пока считаются двумя событиями: поиск похожих отчётов не реализован. Ошибку состава исправляем отменой и подачей нового отчёта.

При ошибке публикации после сохранения бот сообщит номер отчёта. Повторно подавать его не нужно: актуальный статус доступен через `/мп посмотреть`. Отмена сохраняется даже при недоступности публикации.

Если сообщение об отмене не обновилось, повторите `/мп отменить` с тем же номером и причиной. Это повторит обновление сообщения; очки, первоначальная причина и запись отмены в журнале останутся прежними.

При сбое обновления состава черновик не принимает непоказанные изменения. Следующее подтверждение сначала заново показывает сохранённый состав. Проверьте его и нажмите подтверждение ещё раз.

Обращения к SQLite выполняются последовательно в отдельном потоке: ожидание базы не блокирует ответы Discord. Неожиданные ошибки записываются с названием файла, номером строки и цепочкой вызовов, но без текста исключений, значений переменных и HTTP-запросов.

## Проверки и резервная копия

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe backup.py
```

Проверки не подключаются к Discord: они проверяют расчёты, отмену, повторное подтверждение, одновременные клики, права, интерфейс команд, границы недели, перезапуск и резервную копию работающей базы с WAL.

Копии создаются в `backups/` с датой UTC в имени. Дополнительные копии храните отдельно от сервера. Для восстановления остановите бота, сохраните текущую папку `data` целиком, затем создайте новую `data` с выбранной копией под именем `lafamily.sqlite`. Старые `-wal`/`-shm` к восстановленной копии не переносите. Для другого `DATABASE_PATH` используйте соответствующий путь.

## После переноса с JavaScript

Рабочая версия полностью на Python, Node.js больше не нужен. Файл `.env`, папки `data` и `backups` при переносе не заменяются. Схема SQLite и формат дат совместимы с первой версией.

Не запускайте старого и нового бота одновременно с одним токеном и одной базой. При переносе на другой компьютер создайте `.venv` заново: виртуальное окружение нельзя копировать между компьютерами.

## Архитектура и хранение данных

Бот — модульный монолит: один процесс Python, один клиент Discord и общая SQLite. Команды, кнопки и меню вызывают функциональные модули; операции хранения проходят через `DatabaseWorker` и `Store`. Сообщения и их редактирование направляются в `PriceService`.

```text
Discord → FamilyBot → команды / кнопки / меню → функциональная логика
                                                ↓
                                  DatabaseWorker → Store → SQLite
```

Для МП и цен интерфейс, обработка команд и бизнес-логика разделены по файлам. Коровник реализован компактным отдельным модулем.

Баланс не хранится отдельным изменяемым числом: статистика суммирует ставки неотменённых отчётов с участником в составе. Отчёты коровника участвуют в том же расчёте. Отмена исключает начисление, сохраняя историю. Время хранится в UTC, даты и границы недель отображаются и рассчитываются по Москве.

| Данные | Таблицы SQLite |
|---|---|
| Настройки канала и ролей | `settings`, `settings_roles` |
| Виды, отчёты и составы | `event_types`, `reports`, `report_members` |
| Коровник | `barn_settings`, `barn_collections` |
| Канал цен и связи исходников со сводками | `price_settings`, `price_publications` |
| Подписки и состояние уведомлений | `price_subscriptions`, `price_alert_cursor` |
| Журнал действий | `audit_log` |
| Заявки и их доставка | `onboarding_settings`, `onboarding_requests` |
| Анонсы, шаблоны и попытки | `announcement_settings`, `announcement_templates`, `announcement_schedules`, `announcement_attempts` |
| Обновления бота | `release_settings`, `release_deliveries` (прежняя `release_publications` сохранена для совместимости) |
| Служебные отчёты и история ЛС | `admin_report_settings`, `price_delivery_runs`, `price_delivery_attempts` |
| Настройки бэкапов | `database_backup_settings` |

Черновики МП и временные меню живут в памяти. Подтверждённые отчёты, настройки, подписки и состояние публикаций сохраняются после перезапуска. Транзакции защищают связанные записи, идентификаторы запросов — от повторного начисления, а блокировки — от одновременных кликов.

## Коровник

ID опубликованной карточки сохраняется в отчёте. `/мп отменить` обновляет её статус и исключает баллы. Для старого сбора без сохранённого ID бот ищет свою карточку по точному номеру в исходном канале; для поиска нужно чтение истории. Удалённую карточку восстановить таким способом нельзя, но отмена баллов сохраняется.

Администратор задаёт фиксированную награду:

```text
/коровник настройки баллы:5
```

Любой участник сервера может записать сбор:

```text
/коровник сбор сумма:+157к
/коровник сбор сумма:157000 участник:@Игрок
```

Без параметра `участник` баллы получает автор команды. Выбор другого участника доступен также обычному пользователю; отдельного согласования нет. Боту начислить баллы нельзя. Сумма принимается целым числом от 1 до 1 000 000 000, в том числе с пробелами или суффиксом `к`/`k`.

Награда начисляется за один сбор и не зависит от суммы. До первой настройки награды сборы не принимаются. Новая ставка действует только на новые сборы.

Сумма, отчёт и участник сохраняются одной транзакцией. Отчёт «Коровник — сбор» входит в общую статистику; руководство может отменить его через `/мп отменить` по номеру карточки. Карточка отправляется в канал вызова команды. При ошибке ответа уже сохранённое начисление остаётся в базе: повторно вводить команду не нужно. Повторная доставка одного взаимодействия не удваивает награду, но новая команда считается новым сбором.

## Заявки на роль

`/заявки настройки начальный-чат:#вступление админский-чат:#заявки роль:@Участник` доступна руководству и администратору. Заявки проверяет только администратор Discord. Боту нужны управление ролями и никнеймами; его роль должна быть выше выдаваемой роли и всех ролей участника. Выдаваемая роль не может быть управляемой, @everyone или давать administrator.

Постоянная кнопка открывает анкету: два слова имени латиницей и положительный Static ID до 12 цифр; итоговый ник должен помещаться в 32 символа. Администратор может исправить данные и утвердить заявку либо отклонить её с причиной. При утверждении меняется ник, выдаётся роль и отправляется личное уведомление; при отказе участник получает причину.

Данные сохраняются до отправки карточки, а кнопки отправляются вместе с ней. Если привязка сообщения прервалась, кнопка восстановит её после перезапуска. При сбое обновления уже обработанной карточки снова нажмите её кнопку проверки: повторной выдачи роли и нового решения не будет. При явном отказе доставки ЛС появляется кнопка повторного уведомления. Неоднозначная доставка и прежние уведомления старой версии автоматически не повторяются. Повторная настройка публикует новую входную форму.

Карточки, отправленные старой версией без записи в БД или без кнопок, нельзя автоматически связать с заявкой: для них нужна новая анкета. Новые заявки защищены от такого разрыва сохранением до отправки.

Подпись обработанной карточки показывает «Утвердил: имя администратора» или «Отклонил: имя администратора». При восстановлении используется автор сохранённого решения. Если его имя получить нельзя, выводится нейтральная подпись без числового ID. ID остаётся в БД для истории. Прежние сообщения изменятся только при обновлении соответствующей карточки.

## Проверка никнеймов

`/ники проверить роль:@Участник` проверяет отображаемые имена только участников с выбранной ролью, включая офлайн. Поле `роль` необязательное: без него команда `/ники проверить` проверяет всех участников сервера. Наличие дополнительных ролей не исключает участника из проверки. Роль задаёт фильтр проверяемых игроков, а запуск команды по-прежнему доступен только администратору. Если выбранной роли ни у кого нет, бот сообщает об этом. Если ник на сервере не задан, проверяется отображаемое имя Discord. Форматы:

- `Sin Bertoni | 15096`
- `Зам. | Sin Bertoni | 15096`
- `Глава | John Smith | 12345`

Должность — необязательный непустой префикс с отдельным `|`. Имя и фамилия — два слова латиницей (допустимы дефисы и апострофы), Static ID — положительное число. Регистр букв не проверяется. Боты пропускаются, пользовательские ники не меняются. Полный список запрашивается через Discord API, а не из кэша; при сетевой ошибке или тайм-ауте неполный результат не выдаётся за полный.

Для доступа к списку участников нужны **Server Members Intent** в Developer Portal и `DISCORD_MEMBERS_INTENT=true` в `.env`. Включайте флаг в `.env` только после настройки в портале. По умолчанию флаг выключен, чтобы обновление не мешало запуску существующего бота.

### Уведомить участников с неправильными никами

Если проверка нашла нарушения, в личном отчёте появятся кнопки **«Уведомить участников»** и **«Не тегировать»**. Там показаны канал отправки, число получателей и количество сообщений. До подтверждения никто не уведомляется.

Подтверждать может только запустивший проверку администратор; право администратора проверяется повторно при нажатии. Подтверждение действует до 14 минут. Отмена, истечение срока и перезапуск бота не отправляют уведомлений.

После подтверждения бот повторно запрашивает список участников и исключает уже исправивших ник, вышедших с сервера и потерявших выбранную роль. Новые нарушители, которых не было в исходном отчёте, в отправку не добавляются. В тот же канал отправляется просьба исправить ник с личными тегами, по 20 человек в сообщении. Упоминания ролей и `@everyone` отключены. Боту нужны права просмотра и отправки сообщений в этот канал.

Повторный клик той же кнопки не отправляет сообщения заново. При сбое посередине отправка останавливается: администратор видит число подтверждённых отправок и размер группы с неопределённым результатом. Автоматического повтора нет, чтобы не дублировать теги. Отдельная новая проверка с новым подтверждением считается новым уведомлением.

## Сравнение цен скупщиков

Бот читает полные отчёты в одном настроенном текстовом канале, например `💲│цены-скупщика-максималка`, и публикует рядом своё сообщение. **После очистки остаётся последний успешно обработанный исходник и его сводка, а также закреплённые сообщения.** Поддерживаются обычный текст, embeds webhook-сообщений и нативные пересылки Discord.

- ✅ и жирным выделена максимальная текущая цена каждого товара среди трёх скупщиков сырья. При равенстве выделяются все лучшие цены. Обычная и бонусная цена сравниваются отдельно.
- 🏆 означает цену в пределах **95–100%** справочного максимума (включая обе границы). ⚠️ — цену от **90% до 95%**, не включая 95%. Кубок и предупреждение не ставятся одновременно. Лучшая цена среди скупщиков может иметь одновременно ✅ и 🏆 либо ⚠️. Если отметки обычной и бонусной цены отличаются, есть уточнение «обычная» / «+20%».
- Цены продуктов тоже проверяются по справочному максимуму, но не участвуют в сравнении трёх скупщиков сырья.
- Каждый скупщик выводится в отдельном широком блоке с рамкой (Discord Components V2). Жирное выделение и ✅ сохраняются; блоки кода не используются.
- При неполном или неизвестном формате бот не публикует частичное сравнение. Если уже есть успешная публикация, очистка может удалить такое сообщение как постороннее, если оно не закреплено.
- Повторные события одного сообщения не создают копии, в том числе после перезапуска. При редактировании исходника существующее сравнение обновляется. После неопределённой ошибки отправки автоповтор для этого сообщения блокируется, чтобы не создавать дубли. Исходник не удаляется этой ошибкой, но позднее может попасть под очистку после успешной обработки более нового отчёта.

### Включение

1. В Developer Portal → Bot → Privileged Gateway Intents включите **Message Content Intent**.
2. В `.env` добавьте `DISCORD_MESSAGE_CONTENT_INTENT=true`. По умолчанию флаг выключен; остальные функции работают без него.
3. В канале цен дайте боту права просмотра, отправки сообщений, вставки ссылок, чтения истории и **управления сообщениями**. Последние два права нужны для очистки; без них сравнение работает, но очистка пропускается с записью в журнал.
4. Обновите файлы на хостинге и перезапустите `main.py`; команды зарегистрируются автоматически.
5. Руководством или администратором выполните `/скупщик настройки канал:#цены-скупщика-максималка`. Новые отчёты будут обработаны автоматически.
6. Для уже опубликованного исходника выполните `/скупщик обработать сообщение:ID_сообщения`. ID копируется в контекстном меню сообщения при включённом режиме разработчика Discord.

Максимумы со скриншота находятся в `lafamily/modules/prices/limits.json`: `base` — обычная цена, `bonus` — после 3 часов в игре (+20%). Там можно обновить справочник, затем перезапустить бота. Никаких реальных игровых цен из интернета бот не загружает.

Команды `/скупщик настройки` и `/скупщик обработать` доступны руководству (любая из ролей, заданных в `/бот настройки`) и администраторам. Организатор без роли руководства управлять каналом цен не может. Справка `/инфо админ` отражает этот доступ.

Чтобы обновить оформление уже обработанного отчёта без повторной публикации, выполните `/скупщик обработать сообщение:ID_исходного_сообщения`. Бот обновит своё существующее сообщение и уберёт прежние embed-карточки. Исходник сохранится.


### Очистка канала цен

Явный отказ Discord при создании сводки (например, запрет отправки) допускает повтор `/скупщик обработать` после исправления причины. Сетевой обрыв, таймаут или ошибка сервера могут означать уже доставленное сообщение: такие отправки повторно не выполняются.

После успешной обработки бот оставляет последний успешно обработанный исходник, соответствующую сводку, текущие уведомления прежнего формата и все закреплённые сообщения. Новый распознанный исходник, ожидающий обработки, временно сохраняется. Остальные незакреплённые сообщения, включая старые отчёты цен и посторонние сообщения, удаляются. Исторические карточки других модулей этого бота сохраняются. Закрепление проверяется повторно непосредственно перед удалением.

Канал цен нельзя назначить каналом отчётов МП, заявок, анонсов, хранения картинок, обновлений, бэкапов или служебных отчётов; проверка действует при любом порядке настройки. Нельзя создавать в нём черновики МП или начисления коровника. Каналы с сохранёнными отчётами, заявками и картинками также защищены. При прежней конфликтующей конфигурации очистка отключается до перенастройки каналов.

Очистка вызывается также при повторной обработке уже опубликованного отчёта и поступлении нераспознанного сообщения, если в канале есть успешная публикация. Ручная обработка старого исходника не очищает канал, если уже существует более новый успешно обработанный исходник.

### Подписки на максимальные цены

Команда `/скупщик подписки` открывает личное меню с выбором нескольких товаров.
Текущие подписки уже отмечены. Выберите нужные товары и нажмите «Подтвердить».
До подтверждения изменения не сохраняются; «Отмена» закрывает меню без сохранения.
Чтобы отключить все уведомления, снимите все отметки и подтвердите пустой выбор.
Меню действует 10 минут. При сохранении непустого выбора проверяется доступ участника к каналу цен.

Бот отправляет каждому подписчику личные сообщения Discord (ЛС) по выбранному режиму обычной цены: «95 - 100» или «Макс. цена» (подробности ниже). Для продуктов проверяется единственный продавец.
Бонусная цена +20% не используется как отдельный порог из-за округления.
Уведомления содержат товар, цену и ссылку на исходный отчёт. Разрешите ЛС от участников сервера. Закрытые ЛС, уход с сервера и другие ошибки доставки журналируются отдельно для каждого получателя; остальные подписчики продолжают получать сообщения. Публичной отправки при сбое нет, подписка сохраняется.
Проверка начинается со следующего нового автоматически обработанного полного отчёта.
Повторное уведомление возможно после выхода цены из выбранного условия и нового входа.

При неоднозначной ошибке отправки автоповтор уведомления отключён во избежание дублей;

### Справка

- `/команды` — полный список всех команд по разделам, без описаний и параметров. Доступен любому участнику, в том числе без назначенных ролей; ответ личный. Наличие команды в списке не даёт права её выполнять.
- `/инфо общее` или `/помощь` — команды участников и подача отчётов: параметры, пояснения, права и примеры. Настройки и управление в этом разделе не описываются.
- `/инфо фарм` — инструкция участнику: значки и категории цен, выбор товаров и режимов, уведомления в ЛС, повторные сигналы, отписка и коровник.
- `/инфо админ` — отдельная личная справка для руководства и администраторов: настройки, управление МП, вступление и проверка ников, анонсы, отчёты доставки и CSV. У каждой команды указаны её реальные права: доступ к справке не даёт руководству права выполнять команды администратора Discord.

Список, параметры и права берутся из зарегистрированных команд; подробные пояснения охватывают все 38 команд. Длинная справка разделена на страницы с кнопками «Назад» и «Далее», доступными только открывшему её пользователю. В обоих разделах `/старт` есть переход к `/инфо админ`. В первом шаге `/старт админ` также дана ссылка на [репозиторий с кодом бота](https://github.com/Ahero4/lafamily-bot).

Справка видна только вызвавшему участнику. `/старт участник` открывает личное приветствие с первыми шагами, `/бот статус` публикует готовность бота в текущем канале. При каждом запуске `main.py` набор команд регистрируется автоматически.


## Победа и MVP на мероприятии

Руководство или администратор задаёт базовую ставку и необязательные бонусы одной командой:

```text
/мп виды добавить название:Капт очки:10 очки-победы:15 очки-mvp:5
```

Чтобы отредактировать существующий вид, выберите его точное название из подсказок. ID, история и связь отчётов сохраняются, пересоздавать вид не нужно:

```text
/мп виды добавить название:Капт очки:20
/мп виды добавить название:Капт очки-победы:25
/мп виды добавить название:Капт очки-mvp:0
```

Для нового вида базовые `очки` обязательны, пропущенные бонусы равны нулю. При обновлении все пропущенные ставки сохраняются. Явный 0 отключает бонус. Положительные `очки-победы` включают обязательный выбор итога; 0 выключает его. `очки-mvp:0` отключает MVP. Команда `/мп бонусы` заменена этой настройкой. Совпадение названия отключённого вида включает его снова с тем же ID.

Организатор выбирает результат и MVP в форме подтверждения отчёта, а не в параметрах `/мп создать`. Меню результата появляется, если включён выбор итога; до выбора Победа / Без победы сохранить отчёт нельзя. Меню MVP появляется при положительной награде MVP. Выбирать можно одного участника состава, кроме ботов; выбор не добавляет его в состав автоматически. Очистка выбора в меню снимает MVP. Результат и MVP можно менять до сохранения, начисления сразу видны в форме. После очистки состава при необходимости снимите MVP или добавьте его обратно. Настройки наград фиксируются при создании черновика.

Пример: обычная ставка 10, победа +15, MVP +5. За победу каждый получает 25, выбранный MVP — 30. Без победы каждый получает 10, MVP — 15. Без выбора MVP дополнительная индивидуальная награда не начисляется. Баллы появляются только после итогового подтверждения организатором.

Черновик показывает итог, очки каждому и отдельную награду MVP. Все настройки фиксируются при создании черновика. Изменение ставок не меняет старые черновики/отчёты. Личная, недельная и общая статистика включают оба бонуса; отмена исключает всё начисление. Старые отчёты сохраняют прежние очки. Колонки SQLite добавляются автоматически при следующем запуске, рабочая БД при разработке не изменялась.

После обновления перезапустите `main.py` на хостинге — регистрация команд выполнится автоматически.


## Расчёт недельной премии

Только администратор Discord может вызвать:

```text
/баллы премии банк-денег:1000000 неделя:Прошлая
```

`банк-денег` — обязательная сумма целыми долларами от 1 до 1 000 000 000. `неделя` — текущая или прошлая; по умолчанию прошлая. Период: понедельник 00:00 Москвы включительно — следующий понедельник исключительно.

Выплата = банк × баллы участника / сумму баллов всех участников за неделю. Учитываются МП, бонусы победы/MVP и коровник; отменённые отчёты исключены. Участники с нулём баллов не участвуют, при нуле общих баллов расчёт завершается понятной ошибкой. Список не ограничивается страницей рейтинга или текущим составом сервера.

Сначала суммы округляются вниз до целых долларов, затем оставшиеся доллары получают участники с наибольшими дробными остатками; при равенстве — по возрастанию числового Discord ID. Итог выплат всегда равен банку. Например, при банке $100 и баллах 1 и 2 выплаты составят $33 и $67.

Ответ личный: период, банк, общие баллы, приблизительная цена балла и суммы к выдаче. Для более 20 участников показаны первые 20 и приложен полный CSV с ID, баллами и суммами. Упоминания не уведомляют участников. Команда только рассчитывает деньги к выдаче: не переводит их, не списывает баллы, не закрывает неделю и не фиксирует факт выплаты. Повторный запуск использует актуальные отчёты на момент расчёта.

После обновления перезапустите `main.py` на хостинге — команда зарегистрируется автоматически.

## Режимы уведомлений о ценах (0.2.5)

Перед каждым личным уведомлением запрашиваются актуальные роли участника и проверяется просмотр канала цен. При отсутствии доступа ЛС не отправляется, подписка сохраняется; пропуск фиксируется в истории как отказ доступа. После ошибки отображения меню выбор откатывается и повторно показывается перед сохранением.

В `/скупщик подписки` выберите товары, затем область настройки («Все выбранные товары» либо отдельный товар), затем режим **95 - 100** или **Макс. цена**. Можно сначала применить общий режим и затем переопределить отдельные товары. Только «Подтвердить» сохраняет изменения; отмена и истечение 10 минут ничего не меняют. Пустой список отключает все подписки.

Режим «95 - 100»: лучшая обычная цена товара находится в диапазоне 95–100% локального справочного максимума включительно. Выше 100% в этот режим не входит. «Макс. цена»: лучшая обычная цена достигла максимума или выше. Бонусная цена +20% не используется для порога. Повторных тегов внутри условия нет; новый тег возможен после выхода из условия и нового входа. Рост с 95% до 100% не вызывает второй тег для режима диапазона. Смена режима начинает новый цикл только изменённого товара, повторное сохранение того же режима сохраняет защиту от дублей. Ручная обработка старых отчётов не уведомляет.

Старые подписки автоматически получают режим «Макс. цена» с сохранением флагов уведомлений; миграция SQLite выполняется при старте. Оба типа текущих уведомлений прежнего публичного формата сохраняются очисткой до следующей сводки. Новые уведомления отправляются в ЛС. Обновите код и перезапустите main.py на хостинге.

### Подсказки в меню подписок (0.2.9)

## Черновики МП и оформление уведомлений (0.2.11)

Черновик МП действует один час с момента создания, клики не продлевают срок. Завершение и замена редактируют обычное сообщение через API бота, поэтому истечение токена исходной команды через 15 минут не мешает убрать кнопки. Каждый клик обрабатывается новым взаимодействием. После перезапуска несохранённые черновики по-прежнему нужно создавать заново. Выбор результата отмечается в самом меню и сохраняется при других действиях формы.

Уведомления скупщика показывают, например, **Бензин: $200 ($240)**, а номер после «Скупщик» выделяется жирным. Бонус берётся из исходного отчёта; если его нет, приближённый расчёт остаётся явно помеченным. Пороги подписок не менялись.


## Добавление из голоса после создания отчёта (0.2.12)

В открытом черновике `/мп создать` нажмите «Добавить из голосового» и выберите канал в личном меню. Доступно автору с действующей ролью организатора, руководству и администраторам. Проверяются права перед открытием и добавлением. Текущий состав выбранного канала без ботов добавляется к прежнему составу, без дублей; общий лимит 100. Повторный выбор позволяет обновить снимок или добавить людей из другого канала, прежние участники не удаляются. Выбранный канал становится каналом МП, и последующая самозапись требует присутствия именно в нём. Это разовый снимок, не непрерывное отслеживание присутствия. Личное меню выбора действует до 5 минут и не продлевает часовой срок черновика. При истечении/сохранении/замене черновика выбор недоступен. Параметр голосового канала при создании команды сохранён.


## Анонсы мероприятий за 15 минут (0.3.0)

Группа `/анонс` доступна только администраторам Discord. Шаблоны независимы от видов МП и не создают отчётов/баллов.

1. Для картинок задайте отдельный служебный канал: `/анонс настройки хранилище:#картинки-бота`. Нужны просмотр, отправка, вставка ссылок, чтение истории и прикрепление файлов. Не используйте очищаемый канал цен.
2. Создайте шаблон: `/анонс шаблон название:Капт канал:#анонсы роль:@Участники текст:Сбор в голосовом картинка:<прикреплённый файл>`. Картинка необязательна; PNG/JPEG/WEBP/GIF до 8 МБ. Она копируется в хранилище, а в базе сохраняются ID канала, сообщения и вложения. Перед отправкой бот получает актуальный URL вложения и вставляет картинку в карточку, без локального файла и повторной загрузки картинки на хостинг. Не удаляйте исходный пост. При недоступности картинки будет отправлен текст с пометкой и записью ошибки в журнале.
3. Точное совпадение названия обновляет шаблон без смены ID. Повторите команду с новым текстом/ролью/каналом, при необходимости прикрепите новую картинку. Без картинки старая сохраняется; `убрать-картинку:True` удаляет привязку. Изменения применяются к следующим анонсам всех расписаний шаблона.
4. Разово: `/анонс разово шаблон:Капт начало:2026-11-05 20:00` (шаблон выберите из подсказок). Указывать время начала по Москве, не время отправки; до начала минимум 15 минут.
5. Повтор: `/анонс расписание шаблон:Капт дни:пн,ср,пт время:20:00`. Поддерживаются дни пн–вс или `ежедневно`, время по Москве.
6. `/анонс список` показывает ID шаблонов и расписаний. `/анонс отключить номер:…` отключает конкретное расписание. Для изменения времени отключите старое расписание и создайте новое. Не создавайте дубли одного события, иначе независимые расписания отправят отдельные сообщения.

В канале анонсов нужны просмотр, отправка сообщений, вставка ссылок. Роль должна быть упоминаемой или боту нужно право упоминать все роли в этом канале. @everyone не допускается. Отправка разрешает упоминание только выбранной роли, блокируя остальные роли и пользовательские теги в тексте.

Планировщик проверяет расписание каждые 30 секунд. Анонс отправляется в интервале от 15 минут до начала события; указывает точное время и оставшееся время. Если бот перезапустился в этом интервале, анонс будет отправлен после подключения. После начала события пропущенные уведомления не отправляются. Каждое расписание и время начала имеют отдельную запись попытки: повторы/перезапуски не дублируют теги. При неоднозначной ошибке отправки автоповтор не выполняется, чтобы избежать двойного уведомления; проверьте журнал и канал. Ошибки доступа до отправки допускают повторную попытку до начала МП.

Настройки, шаблоны, расписания и попытки хранятся в SQLite. Картинки хранятся в Discord. Для работы по расписанию бот должен оставаться онлайн; данные SQLite на хостинге должны сохраняться при передеплое. После обновления загрузите код, pyproject.toml, CHANGELOG.md и перезапустите main.py — команды зарегистрируются автоматически.


### Админские отчёты и динамика доставки скупщика (0.3.1)

Только администратору Discord:

- `/бот отчёты канал:#админы` — выбрать отдельный текстовый канал служебных отчётов. Боту нужны просмотр и отправка сообщений. Канал цен выбрать нельзя (и наоборот).
- `/бот отчёты` без канала — отключить публикацию отчётов. Сбор истории в БД продолжается.
- `/скупщик статистика дней:30 вид:Таблица` или `вид:Список` — динамика за 1–366 календарных дней до сегодня включительно, по Москве. Ответ видит только инициатор.
- `выгрузка:Да` — приложить `buyer-daily.csv` и `buyer-deliveries.csv` за весь выбранный период. В сообщении показаны последние 10 дней с рассылками. До 50 000 строк подробной выгрузки; при превышении нужно сократить период. CSV: UTF-8 с BOM, разделитель `;`, ID Discord при импорте задавайте как текст.

После каждой рассылки с реальными попытками бот публикует снимок числа подписчиков, число уникальных получателей, скольким отправлено хотя бы одно ЛС, число успешных сообщений, ошибок, неподтверждённых и незавершённых попыток. Один человек с несколькими товарами — один получатель и несколько сообщений. Успех означает подтверждение отправки Discord, прочтение бот не определяет.

В новых таблицах `price_delivery_runs` и `price_delivery_attempts` сохраняются время UTC, источник, снимок подписчиков и каждая попытка (пользователь, товар, режим, состояние и тип ошибки без её текста). Флаги подписки и pending-попытки фиксируются в одной транзакции до отправки. Ошибки ЛС одного участника не прерывают остальных. При неоднозначном сетевом результате — `uncertain`, после прерывания процесса незавершённые попытки остаются `pending`; автоповтора нет. Ошибка админского отчёта не меняет результаты ЛС, результат отчёта также записывается.

Дневная сводка считает людей уникально за день, сообщения — по всем попыткам; один человек может иметь и успешные, и неуспешные сообщения. Число подписчиков — снимок на последнюю рассылку этого дня. Дни без попыток не выводятся. Предыдущие рассылки восстановить нельзя: история начинается после установки обновления. Ручная обработка старого отчёта историю рассылок не создаёт.

После обновления перезапустите `main.py`: таблицы создаются автоматически, команды регистрируются при запуске. История существующих подписок сохраняется.

### Архивы БД в Discord и восстановление (0.5.0)

Все три команды доступны только администратору Discord:

- `/бот бэкапы настройки канал:#бэкапы` — выбрать отдельный текстовый канал. Первая копия отправляется сразу. Боту нужны просмотр, отправка, прикрепление файлов и чтение истории. Используйте закрытый канал: архив содержит всю БД, включая данные участников. Канал цен запрещён, чтобы его очистка не удалила архивы.
- `/бот бэкапы настройки` без канала — отключить автоматическую отправку. Ранее отправленные сообщения не удаляются.
- `/бот бэкапы создать` — отправить архив немедленно. После каждой попытки следующая автоматическая назначается через 6 часов. Настройки и время следующей попытки хранятся в БД; проверка расписания раз в минуту. После простоя делается одна просроченная копия, без пачки за пропущенные интервалы. При ошибке результат записывается в журнал, непрерывного повтора нет; вручную можно повторить сразу.
- `/бот бэкапы восстановить сообщение:ID` — взять ZIP из сообщения этого бота в настроенном канале, проверить его и показать подтверждение на 3 минуты. Права администратора перепроверяются при подтверждении.

Архив содержит `lafamily.sqlite` и `manifest.json`, без кода, `.env` и токена Discord. SQLite Backup API создаёт согласованную копию работающей БД, включая WAL. Сообщение содержит дату по Москве и UTC, тип копии, версию, размер SQLite и ZIP в байтах, число таблиц и записей, активных/отменённых отчётов, участников, подписчиков, учитываемых баллов и SHA-256. Общее число записей суммируется по прикладным таблицам; это не число уникальных людей. Баллы считаются только по неотменённым отчётам. Число участников в истории включает участников отменённых отчётов.

При восстановлении проверяются формат ZIP, состав файлов, размер, SHA-256, версия, сервер/бот, SQLite quick_check, внешние ключи и основная схема. Лишние пути, дубли файлов, триггеры и представления не принимаются. Лимит SQLite — 256 МБ, ZIP — не более 25 МБ и лимита вложений сервера. Это формат архивов бота, а не произвольный архив хостинга.

После подтверждения бот блокирует новые обращения к старому worker и дожидается уже поставленных операций. Создаёт страховочную копию текущей БД в `<папка БД>/backups/` и обязательно отправляет её в канал. Если это не удалось, замена не начинается, исходная БД продолжает работать. Затем старый Discord-клиент и SQLite закрываются; `main.py` переносит данные из проверенной копии через SQLite Backup API и сам создаёт новый worker и клиент. Внешняя ручная перезагрузка контейнера не нужна. При ошибке копирования выполняется возврат к страховочной БД; если и он не удался, запуск прекращается; страховочный ZIP остаётся в папке backups рядом с БД и в Discord. Итог сообщается в канале после подключения.

Восстановление откатывает всю БД: отчёты, баллы, отмены, подписки, расписания и остальные настройки. Отменённый в копии отчёт останется отменённым. История доставки и анонсов также откатывается, поэтому старые события могут считаться неотправленными. Текущий канал бэкапов сохраняется, после восстановления выполняется контрольная автоматическая копия. Меню и неподтверждённые черновики старого клиента закрываются — команды нужно открыть заново. Уже опубликованные Discord-сообщения и выданные роли автоматически не откатываются.

Для применения обновления перезапустите `main.py`, затем задайте канал бэкапов. Рабочую БД храните на постоянном диске хостинга; локальные страховочные копии не заменяют архивы в Discord. Сообщения с архивами автоматически не удаляются.
