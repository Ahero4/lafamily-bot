## Архитектура и карта кода

- `main.py`: config → DatabaseWorker → FamilyBot → bot.start. Закрытие через async context managers.
- `deploy.py`: отдельная регистрация slash-команд на одном сервере, временная БД `:memory:`. Реальный вызов меняет зарегистрированные команды Discord.
- `backup.py`: SQLite backup API с read-only исходником; согласованная копия живой WAL-базы в `backups/`, время UTC в имени.
- `lafamily/bot.py`: FamilyBot, FamilyTree, регистрация модулей, события новых/изменённых сообщений; постоянные EntryView/ReviewView при setup_hook.
- `config.py`: `.env` и относительная БД от корня проекта, вне зависимости от cwd. Переменные процесса имеют приоритет.
- `database.py`: синхронный Store, SQLite WAL, foreign_keys, busy_timeout=5000; BEGIN IMMEDIATE и параметризованные запросы.
- `async_database.py`: DatabaseWorker — один ThreadPoolExecutor worker; создание, операции и закрытие SQLite в одном потоке. database_call поддерживает синхронный Store в тестах.
- `permissions.py`, `access_roles.py`: права all/organizer/manager/admin, администратор имеет полный доступ; любая роль из соответствующего набора достаточна, руководство также организует МП.
- `settings_ui.py`: личная форма наборов ролей, 1–25 в каждом списке, явное сохранение, повторная проверка прав/ролей. @everyone запрещён.
- `info.py`: общая справка строится по зарегистрированным командам и extras.access; снимок настроек без блокирования SQLite в event loop; отдельная справка по фарму.
- `responses.py`, `errors.py`, `diagnostics.py`: UserError показывается пользователю; неожиданные ошибки журналируются с типом, кадрами и цепочкой, без текста исключения и значений переменных.
- `modules/events/`: commands — slash-команды, models — Draft, ui — ReportView, service — подтверждение/публикация/отмена, time — даты/недели.
- `modules/barn.py`: разбор суммы, фиксированная награда за сбор, общий учёт баллов.
- `modules/onboarding.py`: постоянная форма заявки, проверка/исправление/утверждение или отказ администратором; выдача роли, изменение ника, личное уведомление.
- `modules/nicknames.py`, `nickname_notifications.py`: проверка ников через полный API-список; отдельное подтверждение уведомлений, повторный отбор получателей, группы по 20.
- `modules/prices/`: parser — полные отчёты (текст/embeds/snapshots); formatting — Components V2; service — публикация/обновление/очистка; subscriptions — личное меню; notifications — теги при максимуме; limits.json — локальный справочник 20 товаров.
- `tests/`: 16 test_*.py, тесты unittest, Discord подменён mock-объектами; временные/оперативные базы.

## Важные правила поведения

### МП и баллы

- Баланс вычисляется суммой points по неотменённым reports с записью report_members. Отдельного изменяемого баланса нет. Коровник участвует в той же статистике.
- Ставка фиксируется в черновике; последующее изменение тарифа не меняет существующий черновик или отчёт.
- Даты вводятся по Москве, хранятся строками UTC с миллисекундами и Z. Неделя: понедельник 00:00 Москвы включительно — следующий понедельник исключительно. Реализация Москвы — фиксированный UTC+3.
- Старые даты разрешены, будущие запрещены; «Сегодня» и пустая дата фиксируют время создания команды.
- Один активный черновик на организатора и сервер, 14 минут, 1–100 участников, выбор по 25; самозапись сразу в состав, без отдельного согласования. Организатор автоматически не добавляется.
- Необязательный голосовой канал даёт начальный снимок участников без ботов; самозапись затем проверяет присутствие в этом канале. Ручное добавление организатором остаётся возможным.
- Права перепроверяются перед управляющими действиями, lock защищает от параллельного подтверждения, request_id — от повторных начислений.
- Отчёт сохраняется ДО публикации. Ошибка отправки не отменяет начисление; смотреть `/мп просмотр`, не подавать повторно. Отмена исключает очки, сохраняя историю и исходную причину; повтор команды пытается обновить публикацию.

## Обновление 2026-11-03: архивы БД в Discord и восстановление, 0.5.0

По запросу пользователя добавлены /бот бэкапы настройки [канал], /бот бэкапы создать и /бот бэкапы восстановить сообщение:ID; только administrator Discord, права перепроверяются на подтверждении. Всего 38 исполняемых команд, справка и каталог актуализированы. Настройка выбирает отдельный текстовый канал (канал цен запрещён в обеих настройках), первая копия сразу; без канала автоотправка отключается. Нужны view/send/attach_files/read_message_history. Архив содержит данные участников — выбранный канал должен быть закрытым.

BackupStore добавляет database_backup_settings: канал, next_at, last_attempt, state, message_id. Каждая ручная/автоматическая попытка назначает следующую через 6 часов; claim и срок сохраняются до отправки, поэтому рестарт/неоднозначная ошибка не дают непрерывных повторов. После простоя одна просроченная попытка, без пачки пропущенных. poll раз в минуту, start в on_ready идемпотентен, close отменяет/ожидает задачу. Ошибки журналируются без текста исключений и секретов.

export_database выполняет SQLite Backup API в последовательном потоке worker: согласованная копия включает WAL, работающий бот не закрывается. ZIP: ровно lafamily.sqlite + manifest.json (формат 1, сервер/бот, версия, время UTC, SHA-256, статистика). Сообщение: время Москвы и UTC, ручная/плановая/страховочная копия, версия, размеры SQLite/ZIP в байтах, количество прикладных таблиц/записей, активных и отменённых отчётов, уникальных участников истории/активных начислений, подписчиков и учитываемых баллов. Отменённые отчёты в баллы не входят. Код, .env и токен не архивируются.

Восстановление принимает архив из сообщения этого бота только в текущем настроенном канале. Проверяются ID, размер вложения, состав ZIP без лишних/повторных путей, формат/версия/сервер/бот, SHA-256, SQLite quick_check, схема и foreign_key_check; триггеры/представления запрещены. Лимиты: SQLite 256 МБ; ZIP 25 МБ и лимит Discord. Проверочная копия отдельно, миграции только на ней. Показывается дата и число отчётов/участников; подтверждение владельцем за 3 минуты, отмена/таймаут ничего не меняют.

После подтверждения DatabaseWorker.freeze_and_export запрещает новые вызовы и дожидается очереди ранее принятых операций; страховочная БД затем архивируется в <папка БД>/backups и обязательно отправляется в канал. Ошибка до подтверждённой отправки возвращает исходный worker в работу, замена не выполняется. После успешной отправки/ответа client.restore_request передаёт проверочную копию main.py, старый клиент закрывается (фоновые задачи/черновики останавливаются), worker закрывает SQLite. Только после этого apply_restore переносит данные через SQLite Backup API в существующий файл. main.py сам создаёт новый worker/клиент; старые обработчики не получают доступ к новой БД. Канал бэкапов сохраняется; в восстановленную БД пишется audit database.restored с ID источника и страховки. После подключения отправляется итог и новая контрольная копия. При ошибке замены возвращается точная страховочная БД; двойной сбой прекращает запуск, страховочный ZIP остаётся локально и в Discord. Старые меню нужно открыть заново. Discord-посты и выданные роли не откатываются; восстановление откатывает также настройки, отмены и историю уведомлений/анонсов.

Версия/CHANGELOG/README, /инфо админ, /старт админ и /команды обновлены. 236 тестов OK: 216 прежних + 20 новых (WAL, metadata, отмены/баллы, 6 часов/перезапуск/ошибки, лимиты, права, владелец/подтверждение/таймаут, чужие и повреждённые архивы/ZIP traversal/дубли/foreign keys, барьер worker, обязательная страховка, настоящий перенос SQLite, rollback/двойной сбой, полный main.run с созданием нового клиента после закрытия старого).

Рабочая БД/архив пользователя, Discord и хостинг не менялись; проверено только на временных тестовых БД. Commit/push 0.5.0 не выполнялись. Применение: обновить код, перезапустить main.py, затем /бот бэкапы настройки канал:#бэкапы.
